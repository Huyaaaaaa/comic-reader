## 2. 阶段 0：数据库表结构完整迁移

### 2.0 版本化迁移机制（前置）

当前项目使用 GORM `AutoMigrate()` 在每次启动时自动迁移，该方法是幂等的（只做加列、建表），适合简单场景。但本次迁移涉及 `DROP TABLE`、`CREATE TABLE ... AS SELECT`、`ALTER TABLE RENAME` 等不可重复执行的操作，**必须引入版本化迁移机制**。

**方案：基于 `schema_version` 表的顺序迁移**

```go
// 新建 backend/internal/repository/migration.go

// SchemaVersion 迁移版本记录
type SchemaVersion struct {
    Version   int       `gorm:"primaryKey"`
    Name      string    `gorm:"type:text;not null"`
    AppliedAt time.Time `gorm:"not null"`
}

type Migration struct {
    Version int
    Name    string
    Up      func(db *gorm.DB) error
}

// 迁移注册表（按版本号顺序）
var migrations = []Migration{
    {Version: 1, Name: "initial_gorm_auto_migrate", Up: func(db *gorm.DB) error {
        // 保持现有 GORM AutoMigrate 作为 V1，兼容已有数据库
        return db.AutoMigrate(
            &model.Comic{}, &model.ComicImage{}, &model.Tag{},
            &model.ComicTag{}, &model.ComicAuthor{}, &model.ComicMetadataState{},
            &model.ReadingHistory{}, &model.ComicFavorite{},
            &model.ComicListCache{}, &model.DownloadTask{},
            &model.CoverCacheQueue{}, &model.SystemMetadata{},
        )
    }},
    {Version: 2, Name: "add_new_tables", Up: func(db *gorm.DB) error {
        // 新增 users, categories, authors, comic_order_index,
        // comic_cache_state, sync_jobs, app_settings, sources,
        // source_health_checks, search_history
        // 使用 db.Exec(sql) 执行 CREATE TABLE IF NOT EXISTS ...
        return nil
    }},
    {Version: 3, Name: "alter_comics_add_source_fields", Up: func(db *gorm.DB) error {
        // ALTER TABLE comics ADD COLUMN ...（加 IF NOT EXISTS 防护）
        return nil
    }},
    {Version: 4, Name: "rebuild_reading_history", Up: func(db *gorm.DB) error {
        // 备份 → DROP → CREATE → 回填 → DROP 备份
        return nil
    }},
    {Version: 5, Name: "rebuild_download_tasks", Up: func(db *gorm.DB) error {
        // 备份 → DROP → CREATE → 回填 → DROP 备份
        return nil
    }},
    {Version: 6, Name: "alter_comic_images_add_fields", Up: func(db *gorm.DB) error {
        // ALTER TABLE comic_images ADD COLUMN ...
        return nil
    }},
    {Version: 7, Name: "rebuild_favorites_to_user_favorites", Up: func(db *gorm.DB) error {
        // CREATE user_favorites → INSERT FROM comic_favorites → DROP comic_favorites
        return nil
    }},
    {Version: 8, Name: "create_triggers", Up: func(db *gorm.DB) error {
        // 创建 comic_cache_state 触发器
        return nil
    }},
}

// RunMigrations 执行迁移（启动时调用，替代原 autoMigrate）
func RunMigrations(db *gorm.DB) error {
    // 1. 确保 schema_version 表存在
    db.AutoMigrate(&SchemaVersion{})

    // 2. 获取当前最高版本号
    var current int
    db.Model(&SchemaVersion{}).Select("COALESCE(MAX(version), 0)").Scan(&current)

    // 3. 按顺序执行未应用的迁移
    for _, m := range migrations {
        if m.Version <= current {
            continue
        }
        log.Printf("执行迁移 V%d: %s", m.Version, m.Name)
        if err := m.Up(db); err != nil {
            return fmt.Errorf("迁移 V%d (%s) 失败: %w", m.Version, m.Name, err)
        }
        db.Create(&SchemaVersion{
            Version:   m.Version,
            Name:      m.Name,
            AppliedAt: time.Now(),
        })
    }
    return nil
}
```

**对 `repository.go` 的修改：**

```go
// 原来的 autoMigrate(db) 调用替换为：
if err := RunMigrations(db); err != nil {
    return nil, fmt.Errorf("数据库迁移失败: %w", err)
}
```

> **注意：** 已有数据库首次运行新版本时，V1 的 GORM AutoMigrate 仍然是幂等的，会跳过已存在的表。后续版本的迁移只执行一次，不会重复。

**触发器：自动维护 images_local**

```sql
CREATE TRIGGER IF NOT EXISTS trg_images_local_inc
AFTER INSERT ON comic_images
WHEN TRIM(COALESCE(NEW.local_path, '')) != ''
BEGIN
  INSERT OR IGNORE INTO comic_cache_state (comic_id) VALUES (NEW.comic_id);
  UPDATE comic_cache_state
  SET images_local = images_local + 1, updated_at = datetime('now')
  WHERE comic_id = NEW.comic_id;
END;

CREATE TRIGGER IF NOT EXISTS trg_images_local_dec
AFTER DELETE ON comic_images
WHEN TRIM(COALESCE(OLD.local_path, '')) != ''
BEGIN
  UPDATE comic_cache_state
  SET images_local = MAX(0, images_local - 1), updated_at = datetime('now')
  WHERE comic_id = OLD.comic_id;
END;

CREATE TRIGGER IF NOT EXISTS trg_images_local_upd
AFTER UPDATE OF local_path ON comic_images
WHEN (TRIM(COALESCE(OLD.local_path, '')) = '' AND TRIM(COALESCE(NEW.local_path, '')) != '')
   OR (TRIM(COALESCE(OLD.local_path, '')) != '' AND TRIM(COALESCE(NEW.local_path, '')) = '')
BEGIN
  UPDATE comic_cache_state
  SET images_local = images_local + CASE
      WHEN TRIM(COALESCE(NEW.local_path, '')) != '' THEN 1
      ELSE -1
    END,
    updated_at = datetime('now')
  WHERE comic_id = NEW.comic_id;
END;
```

#### sync_jobs（同步/缓存作业表）

```sql
CREATE TABLE IF NOT EXISTS sync_jobs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  job_type TEXT NOT NULL,
  dedupe_key TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL CHECK(status IN ('queued','running','completed','failed','paused','canceled')),
  params_json TEXT NOT NULL DEFAULT '{}',
  cursor_json TEXT NOT NULL DEFAULT '{}',
  progress REAL NOT NULL DEFAULT 0,
  last_error TEXT NOT NULL DEFAULT '',
  next_run_at TEXT,
  started_at TEXT,
  finished_at TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_sync_jobs_status ON sync_jobs(status, updated_at DESC);
CREATE UNIQUE INDEX IF NOT EXISTS uq_sync_jobs_dedupe_active
ON sync_jobs(job_type, dedupe_key) WHERE status IN ('queued', 'running');
```

> **`dedupe_key` 说明：** 用于区分同一 `job_type` 下不同参数的任务。例如 L1 缓存任务的 `dedupe_key` 可以为空（全局唯一），但导入/导出任务的 `dedupe_key` 可以是文件哈希，下载任务可以是 `comic_id`。唯一索引基于 `(job_type, dedupe_key)` 组合，确保同类型+同参数的任务不会重复入队，同时允许不同参数的同类型任务并存。
>
> 创建任务时的 `dedupe_key` 计算逻辑：
> - L1/L2/L3 active 缓存：`dedupe_key = ""`（全局唯一）
> - 内容更新检查：`dedupe_key = ""`（全局唯一）
> - 导入导出：`dedupe_key = sha256(params_json)`
> - 其他按需定义

`ReadingHistory` 删除 `Title`、`CoverURL` 后，历史和收藏列表 API 必须 JOIN `comics` 表来补齐这些字段，否则前端历史/收藏页将无法显示标题和封面。

```go
// repository.go — 历史列表查询改为 JOIN
func (r *Repository) GetReadingHistory(limit, offset int) ([]ReadingHistoryDTO, int64, error) {
    var results []ReadingHistoryDTO
    err := r.db.Table("reading_history h").
        Select("h.comic_id, c.title, c.cover_url, h.last_read_at, h.last_read_sort, h.scroll_ratio").
        Joins("JOIN comics c ON h.comic_id = c.id").
        Where("h.user_id = 1").
        Order("h.last_read_at DESC").
        Limit(limit).Offset(offset).
        Scan(&results).Error
    // ...
}

// 收藏列表同理
func (r *Repository) GetFavorites(limit, offset int) ([]FavoriteDTO, int64, error) {
    var results []FavoriteDTO
    err := r.db.Table("user_favorites f").
        Select("f.comic_id, c.title, c.cover_url, f.created_at, f.ensure_offline").
        Joins("JOIN comics c ON f.comic_id = c.id").
        Where("f.user_id = 1").
        Order("f.created_at DESC").
        Limit(limit).Offset(offset).
        Scan(&results).Error
    // ...
}
```

> **前提：** 收藏/历史中的 comic_id 对应的漫画必须在 comics 表中存在（至少有 L1 缓存）。收藏操作本身会触发 L1 缓存写入，所以正常流程下这个条件总是满足的。

### 3.1 统一 API 响应格式

**修改 `backend/internal/model/dto.go`：**

```go
// ApiResponse 统一响应格式
type ApiResponse struct {
    Data interface{}  `json:"data"`
    Meta ResponseMeta `json:"meta"`
}

// ResponseMeta 响应元数据
type ResponseMeta struct {
    Offline bool   `json:"offline"`
    Stale   bool   `json:"stale"`
    Source  string `json:"source"` // local_cache / remote / hybrid
    Message string `json:"message,omitempty"`
}
```

**修改所有 handler（分批切换 + 前端兼容层）：**

所有 API 返回从 `c.JSON(200, data)` 改为 `c.JSON(200, model.ApiResponse{Data: data, Meta: meta})`。

> **重要：前端兼容策略**
>
> 当前前端响应拦截器（`api/index.js`）直接返回 `response.data`，页面组件按顶层 `items`、`total`、`current_page` 取值。后端全量切换到 `{data, meta}` 格式后，数据会嵌套一层，前端如果不改就会白屏。
>
> **方案：在前端响应拦截器中添加适配层**
>
> ```javascript
> // api/index.js 响应拦截器修改
> api.interceptors.response.use(
>   (response) => {
>     const body = response.data;
>     // 兼容新格式：如果响应包含 data + meta 结构，自动解包
>     if (body && body.meta !== undefined && body.data !== undefined) {
>       // 将 meta 挂到 data 上，供需要的组件访问
>       const result = body.data;
>       if (result && typeof result === 'object') {
>         result._meta = body.meta;
>       }
>       return result;
>     }
>     // 兼容旧格式（尚未切换的接口）
>     return body;
>   },
>   // ...
> );
> ```
>
> **切换顺序：** 先修改前端拦截器（兼容新旧两种格式），再逐个 handler 切换后端响应格式。这样不会出现白屏。

**本地优先策略（关键）：**

```go
// 所有需要网络请求的接口遵循此模式：
func (h *Handler) GetSomething(c *gin.Context) {
    // 1. 先查本地
    localData := getLocalData()

    // 2. 如果有本地数据且不需要在线更新，直接返回
    if localData != nil {
        c.JSON(200, ApiResponse{
            Data: localData,
            Meta: ResponseMeta{Source: "local_cache"},
        })
        return
    }

    // 3. 尝试在线获取（超时 2 秒）
    ctx, cancel := context.WithTimeout(c.Request.Context(), 2*time.Second)
    defer cancel()
    remoteData, err := fetchRemote(ctx)

    if err != nil {
        // 超时或失败，返回本地数据（如果有）
        if localData != nil {
            c.JSON(200, ApiResponse{
                Data: localData,
                Meta: ResponseMeta{Stale: true, Source: "local_cache", Message: "网络超时，显示缓存数据"},
            })
            return
        }
        c.JSON(503, gin.H{"error": "网络不可用且无本地缓存"})
        return
    }

    // 4. 返回远端数据
    c.JSON(200, ApiResponse{Data: remoteData, Meta: ResponseMeta{Source: "remote"}})
}
```

**sort_key 与跨页拼接的职责划分：**

| 场景 | 数据来源 | 排序方式 |
|------|----------|----------|
| L1 缓存不足，列表页需要在线获取 | 远端 API → `comic_list_cache` | 沿用现有跨页拼接逻辑（远端分页 → 本地合并） |
| L1 已有足够缓存，列表页走本地 | `comics` + `comic_order_index` | `ORDER BY sort_key ASC` 本地排序 |
| 搜索/筛选结果 | 远端 API 或本地 LIKE | 各自独立排序，不走 sort_key |
| 收藏/历史列表 | `user_favorites` / `reading_history` | 按 `created_at` / `last_read_at` 排序 |

> 当 L1 缓存覆盖率达到 100%（`active_all` 模式完成后），列表页完全走本地 `sort_key` 排序，`comic_list_cache` 表不再需要。在此之前两套逻辑共存，由 `comic_cache_state` 的覆盖率决定走哪条路径。

## 4. 阶段 2：L1/L2/L3 三层缓存系统

### 4.1 缓存层定义

| 层级 | 内容 | 存储位置 | meta_level |
|------|------|----------|------------|
| L1 | 列表元数据：title, subtitle, rating, rating_count, favorites, category | comics 表 | 1 |
| L2 | 详情扩展：封面(cover_base64)、作者(comic_authors)、标签(comic_tags)、图片总数 | comics + 关联表 | 2 |

type CoverEvictionManager struct {

// 淘汰封面
func (m *CoverEvictionManager) Evict() error {
    limit := m.config.GetInt("cover_limit_value")
    strategy := m.config.GetString("cover_eviction_strategy")

    // 获取已缓存封面数量
    count := m.repo.GetCachedCoverCount()
    if count <= limit { return nil }

    // 获取需要淘汰的数量
    evictCount := count - limit

    // 获取候选列表（排除收藏漫画）
    candidates := m.repo.GetCoverEvictionCandidates(strategy, evictCount)
    // strategy == "lru"：按最后访问时间排序
    // strategy == "fifo"：按缓存时间排序

    for _, c := range candidates {
        m.repo.ClearCoverCache(c.ComicID)
    }
}

## 5. 阶段 3：下载管理器

### 5.1 下载状态机

```
状态定义：
- queued      排队中
- downloading 下载中
- verifying   校验中
- paused      已暂停
- failed      失败
- completed   已完成
- canceled    已取消

允许的状态迁移：
1. queued → downloading          (开始下载)
2. downloading → verifying       (下载完成，开始校验)
3. verifying → completed         (校验通过)
4. queued/downloading → paused   (用户暂停)
5. paused → queued               (用户恢复)
6. downloading/verifying → failed (下载/校验失败)
7. failed → queued               (用户重试)
8. 任意非 completed → canceled   (用户取消)

// GET /api/events — SSE 连接端点
func (h *EventHandler) StreamEvents(c *gin.Context) {
    clientID := uuid.New().String()
    eventChan := h.eventService.Register(clientID)
    defer h.eventService.Unregister(clientID)

    c.Header("Content-Type", "text/event-stream")
    c.Header("Cache-Control", "no-cache")
    c.Header("Connection", "keep-alive")

    c.Stream(func(w io.Writer) bool {
        select {
        case event := <-eventChan:
            data, _ := json.Marshal(event)
            c.SSEvent("message", string(data))
            return true
        case <-c.Request.Context().Done():
            return false
        }
    })
}
```

import { useEffect, useRef, useCallback } from 'react';

export const useSSE = (onMessage) => {
  const eventSourceRef = useRef(null);

  const connect = useCallback(() => {
    const es = new EventSource('/api/events');

    es.onmessage = (e) => {
      const event = JSON.parse(e.data);
      onMessage(event);
    };

    es.onerror = () => {
      es.close();
      setTimeout(connect, 5000); // 5 秒后重连
    };

    eventSourceRef.current = es;
  }, [onMessage]);

  useEffect(() => {
    connect();
    return () => eventSourceRef.current?.close();
  }, [connect]);
};

## 10. 关键设计原则

1. **本地优先**：所有接口优先返回本地数据，网络超时 2 秒后 fallback 本地
2. **前端传参，后端计算**：前端传 page + page_size，后端负责跨网站页拼接
3. **最少在线访问**：有本地缓存就不访问网站，主动缓存通过后台任务完成
4. **三层独立**：L1/L2/L3 各自独立配置，互不影响
5. **渐进式缓存**：passive 模式下用到才缓存，active 模式后台静默缓存
6. **收藏保护**：收藏漫画封面不参与淘汰，ensure_offline 自动触发下载
7. **故障切换**：源站连续 3 次失败自动切换，60 分钟心跳检测
8. **实时反馈**：下载和缓存进度通过 SSE 实时推送
